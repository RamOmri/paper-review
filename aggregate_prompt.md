Three AI models reviewed the paper in this directory independently. Each followed the instructions in review_prompt.md. Their reviews are in gemini.md, gpt.md and claude.md, and the first line of each file names its model. A missing file means that reviewer failed. Say so in the report and work with the reviews you have.

The paper is paper.pdf. The file paper.txt holds its text with margin line numbers, and the folder pages/ holds one image per page.

Judge every point by general academic standards for research in the paper's field. Leave out any point that is only about a venue's rules, such as page limits, templates or anonymity.

Write one report for the paper's author that combines the reviews. Work in this order:

1. Read the whole paper, then read every review.
2. List every distinct point the reviewers raised. Merge points that describe the same issue in different words.
3. Check each point against the paper. Mark it as confirmed, partly right or wrong, and give the evidence. A claim that the paper lacks something it actually contains is wrong.
4. Name the reviewers who raised each point.

Start the report with a level one heading that names the paper. Then write these sections, in this order:

1. A table of each reviewer's model, recommendation and confidence.
2. Points all three reviewers raised. For each point, summarise the feedback the three reviewers gave on it, including the problem, why it matters and the fixes they suggest. Then give your check against the paper.
3. Points two reviewers raised.
4. Points one reviewer raised.
5. Where the reviewers disagree, and which side the paper supports.
6. What to change, as a numbered list with the most important change first. Write each item as plain sentences that tell the author exactly what to add, remove or rewrite in the paper. Do not open items with bold headings, and do not use reviewer shorthand. Tie each item to the points above.

Within sections 2 to 4, put the most serious points first. Write the whole report in plain, professional language. Use ordinary words, and replace any jargon the reviewers used with a plain description of what they meant. Avoid jargon unless no plainer word exists, and never invent terms or labels of your own. Never use metaphors: describe everything literally, and rewrite any metaphor a reviewer used as the literal claim behind it. Write clear, natural prose that the author can understand on the first reading. Explain each problem in plain terms before giving numbers or line references. Define the paper's terms the first time you use them. Give line, table or figure references where they help the author find the problem. Do not use em dashes or en dashes.

Do not create or edit any files. Your final message must be the complete report in Markdown.
